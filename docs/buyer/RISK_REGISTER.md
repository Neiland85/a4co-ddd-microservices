# A4CO Buyer Risk Register

Known limitations for the buyer-ready core preview:

- The buyer baseline is narrower than the full repository.
- Payment is partial and not part of the current buyer gate.
- Auth, product, user and frontend areas require separate review.
- Older documents may describe broader ambitions than the current executable proof.
- Observability is a foundation, not a complete production operations package.
- Persistence maturity should be reviewed per service before production use.
- External access should remain controlled and preferably covered by NDA.

Buyer-facing rule: if a component is not validated by the buyer baseline, present it as partial, future scope or separate review material.
