# Lenguaje comercial seguro ENS/CCN-STIC

## Posicionamiento permitido

Este sistema puede describirse como:

- arquitectura preparada para alineamiento ENS/CCN-STIC;
- baseline técnico ENS-ready;
- sistema con evidencias técnicas reproducibles;
- runtime beta incremental validado;
- preparación inicial para evaluación de controles;
- documentación inicial de activos, riesgos y controles.

## Frases permitidas

- "El sistema no se presenta como certificado ENS."
- "Existe una preparación técnica inicial para alineamiento ENS/CCN-STIC."
- "Se han generado evidencias reproducibles de runtime beta."
- "La arquitectura permite mapear activos, riesgos y controles."
- "El alcance ENS formal dependerá del cliente, entorno, categoría y auditoría aplicable."

## Frases prohibidas

- "Cumple ENS."
- "Certificado ENS."
- "Certificado CCN-STIC."
- "Aprobado por el CCN."
- "Cumple ENS Medio."
- "Cumple ENS Alto."
- "Válido automáticamente para administración pública."
- "Cumple NIST/FIPS."
- "Firma legal cualificada."
- "Cumple eIDAS."

## Preguntas al cliente

1. ¿El sistema se usará en sector público?
2. ¿El contrato exige ENS?
3. ¿Qué categoría requiere el sistema: Básica, Media o Alta?
4. ¿Qué dimensiones son críticas: disponibilidad, integridad, confidencialidad, autenticidad o trazabilidad?
5. ¿Hay datos personales o evidencias sensibles?
6. ¿Se exige auditoría externa?
7. ¿Se exige hosting específico en España o UE?
8. ¿Se exige integración con SOC/SIEM?
9. ¿Se exige backup cifrado, WORM o retención legal?
10. ¿Se exige firma legal/eIDAS o basta firma técnica?
